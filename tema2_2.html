Estructuras de Datos y Arquitectura de Errores

Dejamos los lenguajes estáticos atrás. En C usábamos arreglos estáticos y punteros directos a memoria. Python administra esto con su Recolector de Basura (Garbage Collector). Pasaremos las siguientes semanas manejando tipos de colecciones robustas como Listas, Tuplas y Diccionarios, y modelaremos comportamientos FIFO y LIFO.

Taxonomía de Colecciones Nativas

1. Listas [ ]

Secuencias dinámicas y mutables (editables en runtime). Utilizan mucha memoria pero son muy flexibles.

coords = [10.1, 15.2]
coords.append(20.5)
# Muta la memoria original

2. Tuplas ( )

Secuencias inmutables (solo lectura). Extremadamente rápidas en lectura. Ideales para variables críticas.

home = (19.43, -99.13)
home[0] = 20.0
# TypeError! Crash inminente.

3. Diccionarios { }

Pares Clave:Valor. La estructura principal para bases de datos NoSQL y para configurar objetos de software JSON.

dron = {"bat": 80, "vel": 12}
dron["bat"] -= 10
# El valor se actualiza directo por hash

Stacks (LIFO) & Queues (FIFO)

Modelar abstracciones físicas es parte de la ingeniería de software. LIFO (Last In, First Out) simula el historial de navegación (deshacer paso). FIFO (First In, First Out) procesa colas de tareas o peticiones de red.

# Pila (LIFO) usando una Lista nativa
historial = []
historial.append("GPS_Punto_1")
historial.append("GPS_Punto_2")
reversa = historial.pop() # Saca el Punto_2

Arquitectura Try/Except

En C, atrapar errores de memoria (SegFaults) requería lógica manual. En Python se encapsula en manejadores de excepciones, salvando al software de un colapso total (crashing) en producción.

try:
  velocidad = distancia / tiempo_transcurrido
except ZeroDivisionError:
  print("Error: División por cero (sensor fallido).")
finally:
  print("Liberando socket de memoria...") # Se ejecuta siempre
